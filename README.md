# Bubble

## Назначение

Основной сервис проекта **Bubble**.

Сервис взаимодействует со следующими вспомогательными сервисами:

- [Users](https://github.com/mongolianpes/Bubble-Messenger-Server-Users) — управление пользователями, сохранение сессий и обеспечение TLS;
- [Messenger](https://github.com/mongolianpes/Bubble-Messenger-Server-Messenger) — обмен сообщениями между пользователями, включая специальные сообщения для инициализации и завершения аудиодиалогов, а также передачи файлов;
- [Files](https://github.com/mongolianpes/Bubble-Messenger-Server-Files) — сохранение файлов пользователей;
- [AudioDialog](https://github.com/mongolianpes/Bubble-Messenger-Server-AudioDialog) — организация аудиодиалогов в режиме реального времени.

Для взаимодействия с сервисной частью используется [Клиент]().

## Функционал

- Принимает внешние запросы от пользователей и возвращает информацию в формате JSON.
- Для обработки пользовательских запросов взаимодействует с соответствующими микросервисами по оркестрационной архитектуре.
- Отвечает за расшифровку запросов, за исключением запросов TLS, регистрации и авторизации. Расшифровка данных запросов выполняется сервисом **Users**.
- В сервис встроен автоматический блокировщик IP-адресов, который блокирует клиентов, слишком часто отправляющих невалидные запросы.

## Транспортная безопасность

При обращении через нестандартные порты (используемые Клиентом) применяются собственные механизмы шифрования.

Обмен ключами и аутентификация выполняются через хэндлер `/exchangekey`, который позволяет обменяться с сервером общим секретом с использованием алгоритма **ECDH**.

После выполнения обмена ключами следует сразу использовать хэндлер `/reg` (если пользователь ещё не зарегистрирован), а затем `/auth` для получения долгосрочного общего ключа, которым будут шифроваться передаваемые данные.

### Как работает шифрование

Механизмы шифрования защищают:

- путь в URL;
- тело запроса.

Дополнительно реализована защита от повторной отправки запросов злоумышленником:

- в каждом запросе передаются время отправки и случайная строка;
- сервер сохраняет случайную строку запроса на 30 секунд и отклоняет любые повторные запросы с этой же строкой в течение указанного времени;
- если с момента отправки прошло слишком много времени, запрос также отклоняется.

### Что видит злоумышленник

Злоумышленник может видеть только то же, что и при обычном использовании HTTPS, а также:

- информацию об устройстве (в хэшированном виде);
- остальные данные в зашифрованном виде (логин, пароль, тело запроса, время отправки и случайную строку).
