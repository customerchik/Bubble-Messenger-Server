# Bubble

## Назначение

Основной сервис проекта **Bubble**.

Сервис взаимодействует со следующими вспомогательными сервисами:

- [Users](https://github.com/customerchik/Bubble-Messenger-Server-Users) — управление пользователями, сохранение сессий и обеспечение TLS;
- [Messenger](https://github.com/customerchik/Bubble-Messenger-Server-Messenger) — обмен сообщениями между пользователями, включая специальные сообщения для инициализации и завершения аудиодиалогов, а также передачу файлов;
- [Files](https://github.com/customerchik/Bubble-Messenger-Server-Files) — сохранение файлов пользователей;
- [AudioDialog](https://github.com/customerchik/Bubble-Messenger-Server-AudioDialog) — организация аудиодиалогов в режиме реального времени.

Для взаимодействия с сервисной частью используется браузер, а также доступен [Клиент](https://github.com/customerchik/Bubble-Messenger-Client), функции которого можно использовать для устанавливаемого ПО.

## Функционал

- Принимает внешние запросы от пользователей и возвращает информацию в формате JSON.
- Для обработки пользовательских запросов взаимодействует с соответствующими микросервисами по оркестрационной архитектуре.
- Отвечает за расшифровку запросов, за исключением запросов TLS, регистрации и авторизации. Расшифровка этих запросов выполняется сервисом **Users**.
- В сервис встроен автоматический блокировщик IP-адресов, который блокирует клиентов, слишком часто отправляющих невалидные запросы.

## Транспортная безопасность

При обращении через нестандартные порты (используемые Клиентом) применяются собственные механизмы шифрования.

Обмен ключами и аутентификация выполняются через хендлер `/exchangekey`, который позволяет обменяться с сервером общим секретом с использованием алгоритма **ECDH**.

После выполнения обмена ключами следует сразу использовать хендлер `/reg` (если пользователь ещё не зарегистрирован), а затем `/auth` для получения долгосрочного общего ключа, которым будут шифроваться передаваемые данные.

### Как работает шифрование

Механизмы шифрования защищают:

- путь в URL;
- тело запроса.

Дополнительно реализована защита от повторной отправки запросов злоумышленником:

- в каждом запросе передаются время отправки и случайная строка;
- сервер сохраняет случайную строку запроса на 30 секунд и отклоняет любые повторные запросы с этой же строкой в течение указанного времени;
- если с момента отправки прошло слишком много времени, запрос также отклоняется.

### Что видит злоумышленник

Злоумышленник может видеть только то же, что и при обычном использовании HTTPS, а также:

- информацию об устройстве (в хэшированном виде);
- остальные данные в зашифрованном виде (логин, пароль, тело запроса, время отправки и случайная строка).

## Переменные окружения

Для корректной работы необходимы следующие переменные окружения:

- `USERS_SERVICE_HOST_GRPC_PORT` — адрес и порт сервиса Users;
- `MESSENGER_SERVICE_HOST_GRPC` — адрес и порт сервиса Messenger;
- `FILES_SERVICE_HOST_GRPC_PORT` — адрес и порт сервиса Files;
- `AUDIO_DIALOG_SERVICE_HOST_GRPC_PORT` — адрес и порт сервиса AudioDialog.

## Сборка и запуск

1. Установите Docker, если он ещё не установлен.
2. Используйте скрипт развертывания проекта из папки `docs` (`install.sh` для Linux или `install.ps1` для Windows). Скрипт клонирует репозитории всех сервисов, создаст базы данных в Docker и запустит проект.

Для повторного запуска проекта выполните в директории с файлом `docker-compose.yml` команду:

```bash
docker compose up -d --build
```
